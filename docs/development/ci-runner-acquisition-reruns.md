# CI reruns after GitHub-hosted runner acquisition fails

Research for [Sandman #3031](https://github.com/rafaelromao/sandman/issues/3031), 2026-11-23. Read-only investigation; no Actions runs were started, cancelled, or rerun.

**Finding:** Both targeted and failed-only reruns have requeued a completed `cancelled` job that never acquired a GitHub-hosted runner. Both also reran a dependent gate while carrying forward successful jobs outside the rerun set. This is observed GitHub.com behavior, not a documented guarantee for every cancellation or workflow. Use the targeted operation when recovery must select only verified shortage jobs and their dependents: failed-only selects other failed jobs too.

## What GitHub documents

- [Targeted job](https://docs.github.com/en/rest/actions/workflow-runs#re-run-a-job-from-a-workflow-run): `POST /repos/{owner}/{repo}/actions/jobs/{job_id}/rerun` (`gh run rerun --job JOB_ID`). Reruns the selected job and jobs that depend on it. Use the job database ID from the Actions API, not a number inferred from a URL.
- [Failed jobs only](https://docs.github.com/en/rest/actions/workflow-runs#re-run-failed-jobs-from-a-workflow-run): `POST /repos/{owner}/{repo}/actions/runs/{run_id}/rerun-failed-jobs` (`gh run rerun RUN_ID --failed`). Reruns all failed jobs and their dependents, not just a particular failure.
- GitHub [documents the dependency behavior](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/re-run-workflows-and-jobs): excluded jobs retain previous outputs; reruns retain the original SHA/ref, have a 30-day window and a maximum of 50 reruns, and are disallowed while the workflow is disabled. Neither endpoint specifies whether a never-started `cancelled` job qualifies. The [CLI source](https://github.com/cli/cli/blob/761ea6d6915b74b5479e29e25019d4d9f09e58c7/pkg/cmd/run/rerun/rerun.go) maps the two options to distinct endpoints; it does not determine server-side eligibility.

Readback uses the [attempt jobs API](https://docs.github.com/en/rest/actions/workflow-jobs#list-jobs-for-a-workflow-run-attempt) and [check-run annotations](https://docs.github.com/en/rest/checks/runs#list-check-run-annotations). **A different ID or `run_attempt` on a job row does not by itself prove re-execution.** Compare start/end times and steps for the same logical job. The attempt API does not identify which rerun endpoint started an attempt, so endpoint attribution above comes from the request reports or workflow log, not from job shapes alone.

## Sandman readback and limits

- [Incident run `45270155099`, attempt 1](https://github.com/rafaelromao/sandman/actions/runs/45270155099/attempts/1): `build (macos-latest)` `138027527159` matches the acquisition signature; `quality-gate` `138036364100` failed with “build-macos must succeed (result: abandoned)”. The [workflow at the incident head](https://github.com/rafaelromao/sandman/blob/f454c9077c0c41046fe8429e57777795b66e46a7/.github/workflows/go.yml#L413-L433) declares `quality-gate` with `if: always()` and `needs: [..., build-macos, ...]`. The successful [run `45276896986`](https://github.com/rafaelromao/sandman/actions/runs/45276896986) was a separate PR-edit execution on the same head, also attempt 1, not a rerun.
- [Same-day Sandman run `45209234503`](https://github.com/rafaelromao/sandman/actions/runs/45209234503/attempts/2) showed the exact desired effect: annotated cancelled macOS job `137813205205` → `137823958869` success and `quality-gate` `137823102628` failure → `137829939385` success. All nine other jobs retained their original execution times. This confirms the Sandman gate graph works under partial rerun, but public readback does not identify the initiating endpoint.
- Wait for the original workflow attempt to finish. Treat rejected requests as rejected, and do not equate acceptance with recovery: confirm a fresh job on a higher attempt and evaluate the gate normally. Not every workflow can be rerun; for example, [an observed managed CodeQL run](https://github.com/alexandru-savinov/agterm-omarchy/pull/400#issuecomment-6864700838) refused the targeted request even though its runner acquisition was cancelled. This does not make generic cancellations eligible for automatic recovery or justify a blanket rerun.
